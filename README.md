# Dикие Сочи: архив маршрутов

**Каталог для скачивания GPX: https://donrumata03.github.io/dikiye-sochi-archive/**

Архив сохраняет маршруты из публичных ссылок на Яндекс Диск в канале [@dikiye_sochi](https://t.me/s/dikiye_sochi). OAuth Яндекса и вход в Telegram не требуются. Старые файлы и версии остаются в архиве, даже если исчезают из исходной папки.

## Автоматическое обновление

[GitHub Actions](https://github.com/donRumata03/dikiye-sochi-archive/actions/workflows/archive-tracks.yml) проверяет новые посты и файлы ежедневно в **08:22 по Москве** (05:22 UTC), при изменениях в `main` и при ручном запуске. Расписание GitHub может задерживаться.

Ссылки из новых постов дополняют сохранённые источники. Начальный источник: https://disk.yandex.ru/d/msmGZTv0QtuLhA. При локальной проверке 17 ноября 2026 также найдена https://disk.yandex.ru/d/IePMQmU0SxLt4Q (посты №39 и №42): всего скачаны четыре GPX. Последнее состояние и результат каждого источника находятся в [`data/manifest.json`](data/manifest.json), сами файлы — в [`data/tracks/`](data/tracks/).

При скачивании проверяются размер, MD5/SHA-256 из API; GPX дополнительно разбирается как XML. Существующие копии проверяются перед повторным использованием; повреждённые скачиваются заново. Новая версия файла сохраняется отдельно. Временные загрузки не становятся готовыми файлами.

Ошибки Telegram, источника или отдельного файла отмечают запуск как неуспешный. Уже полученные файлы сохраняются в Git и в резервном артефакте Actions на 30 дней. Если сохранение в Git или сборка сайта не удались, новый сайт не публикуется. При частичном сбое каталог может обновиться с предупреждением о неполной проверке. Проверяйте статус последнего запуска в Actions.

## Локальный запуск

Нужен Python 3.12:

```bash
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python sync.py
python build_site.py
python -m http.server 8000 --directory site
```

Каталог откроется на http://localhost:8000. Папка `site/` генерируется и не хранится в Git.

```bash
python verify_live.py
```

Эта отдельная сетевая проверка скачивает файлы в пустой временный архив, повторяет синхронизацию и проверяет ссылки под `/dikiye-sochi-archive/`. Она не пишет на GitHub и не изменяет основной архив. Результаты записываются в `evidence/live-check.json` и `.log`.

Переменные окружения: `TELEGRAM_CHANNEL` (по умолчанию `dikiye_sochi`), `YANDEX_DISK_URL` (резервный источник), `TELEGRAM_PAGE_LIMIT` (по умолчанию 14). После долгого перерыва лимит можно увеличить. При первом запуске читаются до 14 страниц истории; затем новые сообщения читаются до пересечения с сохранёнными. Старые сообщения, отредактированные за пределами этого окна, могут быть пропущены.

Архивируются GPX, KML, KMZ, FIT, TCX и ZIP; ZIP не распаковывается. Поддерживаются корневые публичные ссылки `/d/<ключ>` и `/i/<ключ>` на `disk.yandex.ru`, `disk.yandex.com`, `disk.360.yandex.ru` и `yadi.sk`; вложенные папки обходятся через API. Лимит одного файла — 90 МиБ. Архив не восстанавливает файлы, удалённые до первого скачивания, и не устанавливает автоматически соответствие между текущим файлом и анонсом похода.

## Отдельный GitHub Pages project site

Pages работает из этого репозитория, источник публикации — GitHub Actions. Используются относительные ссылки; `CNAME` и изменения DNS не нужны. Workflow разрешает публикацию только из репозитория `dikiye-sochi-archive` и ветки `main`. Личный сайт в `donRumata03.github.io` обслуживается независимо.

Проверки pull request запускают только локальные тесты, без скачивания из внешних источников и без публикации. Правила защиты ветки и окружения соблюдаются; если они блокируют автоматическое сохранение, резервная копия доступна в артефактах Actions.
